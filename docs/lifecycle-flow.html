Lifecycle Order Flowchart

The hooks a page author writes, in the order they fire. Only those: no change-detection passes, no router events. Measured, not quoted from docs.

  • Angular
  • Ionic page hook
  • Guard or resolver
  • Old hook, re-created by the shim
  • First visible render
  • awaits Promise the framework awaits what you return (Ionic 3: a Promise; the Angular router: a Promise or an Observable) and navigation pauses until it settles. Load or check data here.
  • return ignored you can write the hook as async, but nothing waits for it; show your own loading state

Where you can wait for data

Only the amber-tagged hooks are awaited: Ionic 3 awaited a returned Promise, the Angular router awaits a Promise or an Observable. Everything else runs and the app moves on, so data loaded there needs its own loading state.

The one thing that does not come back is an ionViewCanEnter that reads instance state. The router decides before the page exists, so the check has to be static or live in a service. If it must see the instance, let the guard pass and check in ionViewWillEnter, then navigate back; that restores "construct first, then decide" at the cost of a possible flash.

·First visible render

There is no "painted" event in either stack. The green box is the earliest point where the page's DOM is complete and the next frame will show it: a requestAnimationFrame after ngAfterViewInit in the old app, afterNextRender in the new one. On a push the page then slides in and is fully visible at ionViewDidEnter. On app start the root page has nothing to leave, so Ionic 8 fires both enter hooks at once, before anything is painted.
